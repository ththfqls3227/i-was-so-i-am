# Phase F 스펙 — 「기억 보관소」: 규모·스토리·클린 챔버 (2026-08-20, 오너 피드백 라운드)

오너 결정: ①아트를 **클린 시험 챔버**(포털 스타일)로 피벗 ②튜토리얼 **마이크로 챔버 3개** 추가, 개념 스텝 바이 스텝 ③Handoff **단순화 재설계** ④한국어 카피 전면 재작성("시간을 접는다" 등 어색한 표현 제거) ⑤**규모 확장** — 짧은 데모가 아니라 스토리 있고 단계별로 깨나가는 게임.
레퍼런스 학습(2026-08-20): 포털 챔버 사인(큰 번호+진행바+메커니즘 픽토그램), 흰 패널+다크 존 대비, 바닥 시안 점선 루트 / 크로노트론(한 방=한 트릭, 개수로 스케일, 레벨 셀렉트).
불변: 결정론 코어 렌더-온리, 런타임 래스터 0, 브라우저 즉시 플레이, `gate:submission` 그린 유지, 커밋 트레일러 규칙.

## F1. 세계관·스토리 (텍스트 몇 줄로 구현되는 아크)
- 무대: **기억 보관소** — 떠난 사람의 하루하루가 챔버로 보관된 시설. 플레이어는 위층(최근 기억)에서 아래층(오래된/깊은 기억)으로 내려간다.
- 딜리버리: ①챔버 입장 시 시설 자막 1~2줄(사무적 톤 → 내려갈수록 인간적 톤으로 변화, 스킵 가능) ②구역 전환 인터타이틀(구역명+한 문장) ③엔딩(기존 이별 비트 유지·강화).
- 감정선: 초반 "보관 절차 안내"처럼 굴던 시설 문구가, 후반 "이 기록을 남긴 것은 당신입니다" 계열로 뒤집히며 제목(I WAS, SO I AM)을 회수.
- 카피 원칙: 대구 구조 반복 금지, 번역투 금지, 실제 게이머 언어. 시적 표현은 구역 전환·엔딩에만.

## F2. 챔버 로스터 (서장 3 + 4구역 = 총 10 플레이 챔버, 증분 설계)
각 챔버 = 새 아이디어 정확히 1개. 뒤 구역은 앞 구역 개념의 조합. 06~08은 시간 부족 시 절삭 가능한 증분(각각 골든+테스트와 함께 커밋).

| # | 구역 | 이름(가) | 가르치는 것 / 퍼즐 |
|---|---|---|---|
| 00 | 서장 | 깨어남 | 이동+발판(신규 plate)을 밟으면 문이 열림. 기록/재생 루프를 부담 없이 통과(협동 불필요) |
| 01 | 서장 | 두 번째 나 | 에코가 발판을 밟고 있어야 문이 열림 — 협동 필수의 최소형 |
| 02 | 서장 | 기록 끝내기 | 현 Crossing 개조: 윈치 잡기 + ⏎ 기록 끝내기 학습 |
| 03 | 1구역 | 몸이 아니라 손 | **blocked-input 트릭**: 기록 중 닫힌 문에 막힌 채 전진+잡기 유지 → 재생 때 (내가 열어준) 문을 뚫고 지나가 스위치를 잡는다 |
| 04 | 2구역 | 함께 드는 무게 | 현 TraceWeight 유지(사인·동선 라인으로 안내 강화) |
| 05 | 3구역 | 열어주는 손 | **Handoff v3 단순화**: 과거가 스위치를 붙들어 게이트를 여는 동안, 현재가 받침대의 상자를 들고 통과해 수구에 넣는다. 릴레이·교차점·리다이렉트 규칙 전부 제거. 코어: 캐리어 픽업의 stagedByPast 전제 제거(픽업 가능 액터를 챔버 데이터로 지정) |

| 07 | 2구역 | 무게의 릴레이 | 과거가 블록을 절반 밀고 홀드로 이동, 현재가 나머지 절반을 이어 민다 (절삭 후보 2) |
| 08 | 3구역 | 되돌아오는 길 | pushDirection left + 왕복 동선 응용 (절삭 후보 3) |
| 09 | 4구역 | 마지막 붙듦 | 현 LastHold 유지 — 피날레 |

- 신규 코어 메커니즘 **1개만**: `plate`(밟고 있는 동안 활성, hold의 무입력 변형; requiredActor 지원, door.gatedBy에 'plate' 추가). 그 외 조합은 기존 메커니즘 재사용.
- 방 크기: 구역이 진행될수록 world 치수·동선 확대(넓어지는 느낌). 후반 챔버 tapeDurationTicks 상한을 20s(600틱)까지 허용 — 관련 유닛테스트의 14s 제약을 챔버별 상한으로 완화.
- 진행 저장: localStorage 진행도 확장(클리어한 챔버 목록). **챔버 선택 화면**: 타이틀에서 구역별 그리드, 클리어한 챔버+다음 챔버만 잠금 해제. `switchChamber` 재사용.

## F3. 아트 피벗 — 클린 시험 챔버
- 팔레트: 오프화이트 패널(#e8e6e0 계열, 미세 그리드 심), 다크 메커니즘 존(#2a2d33), 액센트 시안(과거)·앰버(현재) 유지, 경고 스트라이프 최소 사용.
- 벽: 대형 사각 패널 모듈(프로시저럴 — 패널 심+미세 베벨 노멀), 다크 존은 메커니즘 주변에만. 유리 관측창 1개/방(빈 관측실 — 스토리 장치).
- 조명: 밝고 균일한 주광(천장 스트립 발광) + 소프트 섀도 + 은은한 AO. 어둡고 무디한 볼트 룩 폐기. 포스트: 노출/대비 재조정, 비네트 약화.
- **사인 시스템**(핵심): 입구 사인 패널 = 큰 챔버 번호 + 진행바(01/10) + 이 방 메커니즘 픽토그램 타일(기록·에코·발판·스위치·상자·무게추 아이콘 세트, DynamicTexture 벡터풍). 
- **바닥 루트 라인**: 앰버 실선=현재 동선 제안, 시안 점선=과거(기록) 동선 제안 — 방마다 저작. 골드 타겟 링과 일관.
- 메커니즘 드레싱: 클린 산업 디자인(발판=원형 압력판+링 발광, 스위치=기둥형 레버, 게이트=수직 슬라이드 도어, 상자=흰 큐브+시안 코어 = 컴패니언 큐브 문법).
- 캐릭터: 현행 유지하되 새 조명에 재질 재조정. 에코 additive 품질 유지.
- 썸네일: 새 룩 확정 후 인게임 장면으로 재촬영(1920×1080), reference-v1은 폐기 후보.

## F4. UI 간소화 + 카피 전면 재작성
- 1차 안내=환경(사인·바닥 라인·발광), 2차=튜토리얼 카드. 카드는 **제목 1줄+체크리스트만**으로 축소(본문 설명은 처음 등장하는 개념에만).
- 용어 교체: 「시간 접기」→ **「기록 끝내기 ⏎」** (본문: "지금 자세 그대로 기록을 마칩니다"). "메아리 남은 시간"→"기록 시간" / "재생 시간". 전 카피 자연어 검수: 번역투·한자어 남발·대구 반복 제거. 영문 카피 동반 갱신.
- 패스 표기: "1회차 기록/2회차 협동" 유지하되 배지·배너 문구 자연화.
- 실패 카피: 사실+다음 행동 1문장. failureCopy 전면 재검토.

### F2(W1) 구현 메모 (2026-08-20)

라우트는 **00 깨어남 → 01 두 번째 나 → 02 건너는 기억 → 03 몸이 아니라 손 → 04 무게의 흔적 → 05 이어받은 마음 → 09 마지막 붙듦** 7개로 확정. 스펙과 다르게 간 지점과 그 이유:

1. **plate**: `PlateState`는 원형이 아니라 `Rect` 확장 — 밟음 판정은 액터 중심점의 rect 포함 여부. `requiredActor` 지원. 실행 순서는 `hold → plate → door`.
2. **door 확장 2개**: `gatedBy: "plate"`와 **`latchOnOpen`**(처음 열린 순간 영구 래치). 00번의 "발판이 잠금을 푼다"를 기존 좌표 임계값(`latchWhenPresentBeyondX`)으로 흉내내지 않고 명시 플래그를 새로 뒀다 — 좌표로 표현하면 데이터만 보고는 의도를 읽을 수 없다.
3. **`exitGate: "hold"` 추가**: 03번이 문은 plate에, 출구는 hold에 걸리는 구조라 필요. B4의 exitGate 설계를 그대로 확장.
4. **Handoff v3에서 죽은 것**: `junction` / `stagedByPast` / `receivedByPresent` / `redirectedByPresent` 필드와 규칙 전부 삭제, 실패 코드 `carrier-not-staged` 삭제, 관련 테스트·렌더(교차점 링)·오디오 큐 호출 삭제. **남긴 것**: 캐리어 배타 규칙(다른 액터가 든 상자는 타깃 불가 + 클레임 시 타 액터 targetId 비우기). 챔버 데이터로는 더 이상 도달하지 않지만 메커니즘 자체의 불변식이라, 양쪽이 들 수 있는 synthetic 챔버 테스트로 고정해 두었다. 새 필드는 `carriedBy`(픽업 권한)와 `carriedByPresent`(실패 코드 분기)뿐.
5. **실패 코드**: `+plate-unpressed`, `+carrier-not-carried`, `-carrier-not-staged`. `hold-released-early`는 "출구가 grip에 걸린 방" 케이스까지 확장. 방별 카피는 `roomFailureCopyMap`으로 분기(00번은 협동이 필요 없으므로 두 코드 모두 "다시 기록"이 아니라 이번 패스에서 할 일을 말한다).
6. ~~**03번 정직성 게이트**~~ (아래 F2-a로 대체됨): B5의 `TraceRecordingProjection` 프레임 스테핑 루프를 `projectFrames()`로 추출하고 `HandRecordingProjection`을 **형제 클래스**로 추가(상속 계층 없음). 카드가 fold를 제안하는 조건은 ①문이 열린 챔버 사본에서 메아리가 스위치를 잡는가 ②그 시점 + `handFinishTicks()`가 리플레이 창 안인가. 스위치를 오른쪽 벽에 붙여 **여분 기록 틱이 오버슈트가 아니라 슬랙**이 되도록 지오메트리를 설계했다(메아리가 스위치를 지나치지 못하고 벽에 눌린다). 회귀 테스트는 "제안한 모든 틱에서 성공" + "한 틱 일찍 접으면 메아리가 갇히고 출구가 안 열림".
7. **00/01번은 투영 불필요**: 00번은 협동이 없어 어떤 fold도 doomed일 수 없다(유닛 테스트로 명시 — 빈 테이프로도 클리어). 01번은 "발판 위에 서 있음"이 기록 중 화면에서 관측 가능하므로 라이브 상태로 게이팅.
8. **라우트 상수**: `FOUR_ROOM_ROUTE` → `CHAMBER_ROUTE`(+ `CHAMBER_SECTORS`). 테이프 상한은 14s 단일 제약에서 **서장 8s / 그 외 20s**로 완화.
9. **진행 저장**: 클리어 목록은 성공 카드가 뜨는 순간 저장한다(다음 버튼이 아니라). 마지막 방은 "다음"이 없어 영영 기록되지 않던 구멍이 있었다. 구버전 레코드는 `nextRoom` 앞의 방들을 클리어로 간주해 그대로 로드된다.
10. **오디오**: `AMBIENT_ROOT_HZ`에 3개 방 추가. `handNotBody`는 임시로 crossing과 같은 D2 — 구역별 조성 상승은 W4 몫. `carrier-stage` 큐는 스테이징 제거로 더 이상 트리거되지 않는다(엔진 정의는 오디오 담당이 판단하도록 남겨 둠).
11. **스트레치 06~08 미착수**. 06을 스펙대로("서로의 문을 여는 hold 2개") 만들면 hold가 챔버당 1개인 코어 제약상 새 방이 아니라 01·05의 재탕이 되고, 진짜 교차로 만들려면 03의 blocked-input을 다시 쓰면서 세 번째 투영이 필요하다. 07(무게의 릴레이)은 threshold 1이면 과거 혼자 끝까지 밀어 협동 게이트가 사라지고, 과거를 중간에 멈추려면 fold 꼬리가 손을 유지한다는 규칙과 충돌한다. 둘 다 W1 안에서 정직하게 풀리지 않아 손대지 않았다.

### F2-a 폴드 시맨틱 변경 — 「자세 그대로」 (2026-08-21, 오너 라이브 플레이 발견)

증상(오너 재현): 03번을 카드대로 기록하고 첫 제안 틱에 접은 뒤, 2회차에서 **여유 있게** 발판으로 걸어가면 실패(`메아리가 스위치에 닿지 못했습니다`). 원인은 B1의 fold 꼬리 규칙 — 꼬리가 `ActionHeld`만 남기므로 메아리의 **남은 이동량이 기록 시점에 고정**된다. 2회차에서 꾸물댄 1틱은 닫힌 문 앞에 눌려 있는 메아리의 1틱을 그대로 깎는다. 투영은 문이 0틱부터 열려 있다고 가정하므로 카드의 제안이 느린 2회차에 대해 낙관적이었다 — B5가 없애려던 바로 그 결함 클래스(페이스 의존 doomed fold).

**결정(오너)**: fold 꼬리가 **마지막 샘플 프레임 전체(이동 비트 포함)** 를 유지한다. 「지금 자세 그대로 기록을 마칩니다」가 문자 그대로 참이 된다.

측정으로 확인한 것(수정 전/후):
- 03번 dawdle 0/15/30틱 → 기존도 성공. **60/90틱 → 기존 실패, 자세 꼬리 전부 성공.**
- 반대 방향 위험(신규): 잡고 있어야 하는 방에서 **방향키를 누른 채 접으면 메아리가 걸어가 버린다.** Crossing `walking+grip` → 실패(`door-closed`), Second Self `walking` → 실패(`plate-unpressed`). **둘 다 당시 카드가 fold를 제안하던 상태였다.** 즉 오너 판단의 전제("shipped room의 꼬리는 중립이거나 올바르다")는 *골든*에 대해서는 참이지만 *플레이어가 실제로 누를 수 있는 입력*에 대해서는 거짓이었다.

구현:
1. `postureOf(frame)` — 꼬리는 눌린 키만 남기고 **press/release 엣지를 제거**한다(엣지는 자세가 아니라 사건이며, `ActionReleased`가 반복되면 매 틱 타깃이 풀린다). `Simulation.foldTail` 게터로 UI가 같은 규칙을 읽는다.
2. **03번 게이트 최소화**: 자세 꼬리에서는 `right+action` 기록이면 문이 언제 열리든 메아리가 스위치까지 걸어간다 → 기록이 길이로 doomed 될 수 없다. `HandRecordingProjection` / `handFinishTicks` / out-of-time 카드 **삭제**, 게이트는 「지금 자세가 right+action인가」로 축소. `projectFrames`는 호출자가 하나로 돌아와 Trace 투영 안으로 복귀. 2회차 지각은 라이브 실패로 남기고 카피를 **이번 패스 탓**으로 교정.
3. **grip 방 4개(Crossing/Second Self/Handoff/Last Hold) 카드에 정지 조건 추가**: 발이 멈추기 전에는 ⏎를 제안하지 않고 `*-stop-then-fold` 스테이지로 「방향키에서 손을 떼세요」를 띄운다. Trace Weight는 미는 자세가 정답이라 그대로 둔다.
4. 골든 7개 전부 재검증(꼬리: awakening=right, secondSelf=still, crossing=act, handNotBody=right+act, traceWeight=right+act, handoff=act, lastHold=act). **행동이 바뀐 방은 awakening 하나** — 메아리가 계속 오른쪽으로 걸어가지만 협동이 필요 없는 방이라 무해. traceWeight는 안착 후에도 추에 눌러붙어 밀기만 하고(변위 0) 체크섬 안정, lastHold/handoff/crossing 그립 유지.
5. B5 Trace 매트릭스는 한 어서션이 뒤집혔다: 제안 1틱 전 fold가 「좌초」에서 「늦게 도착」으로 바뀌어 성공한다. 그 테스트를 뒤집어 고정했으므로 **핀 발 꼬리를 되살리면 실패**한다.
6. **부수 수정(게이트 신뢰성)**: traceWeight `tapeDurationTicks` 10s→12s. 2회차 동선(건너기+합류 밀기+안착+추 우회)이 308틱 창에서 여유 2초뿐이라 dist 게이트에서 한 번 창이 터졌다. 방이 요구하는 것은 그대로 두고 창만 넓혔다(구역 상한 20s 이내). 같은 런에서 터진 nudge e2e는 윈치 접근이 "근접 경계 통과 후 키 떼기"라 스로틀 상황에서 반대편으로 지나쳐 잡지 못하던 것 — 짧은 버스트로 수렴하게 교체.
