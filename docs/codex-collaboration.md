# Codex Collaboration Record

이 게임의 토대는 OpenAI Codex와 함께 만들었습니다. 아래는 리포지토리 안에서 확인 가능한 증빙과 함께 정리한 협업 기록입니다.

## 기획은 어떻게 시작됐나

초기 기획은 실제 `$deep-interview --standard`로 진행했습니다. 인터뷰 ID는 `3D974CD3-DB93-4EE8-8794-4F5814D3F106`, 총 8라운드, 최종 모호도는 `0.03`이었습니다. “게임이 너무 짧지 않은가?”에서 출발해 완성감, 장르, 실제 플레이, 방 리셋, 잔상 수, 비목표, 결말 감정을 한 질문씩 확정했습니다.

질문의 핵심 흐름은 다음과 같습니다.

1. 완성감을 시간·레벨 수가 아니라 플레이 뒤 남는 감정으로 다시 정의했습니다.
2. 감정을 고르기 전에 장르가 불명확하다는 점을 발견했습니다.
3. ECHOFOLD를 유지하고 2D 시간루프 선례를 조사했습니다.
4. 사용자가 Portal식 방, 두 번 플레이, 큰 바위 협동 예시를 제시해 자기협동 물리 퍼즐로 고정했습니다.
5. Codex가 전체 리셋과 입력 의도 재생을 선택해 실제 동시 협동을 보장했습니다.
6. 잔상을 한 명으로 제한하고 벌점 없는 재기록을 채택했습니다.
7. “어려운 조작”을 명시적 비목표로 잠갔습니다.
8. 과거의 나와 헤어지는 자기수용의 결말을 최종 감정으로 선택했습니다.

그 뒤 `$ralplan --direct`가 인터뷰 결과를 PRD와 테스트 명세로 바꾸고 Planner→Architect→Critic 검토를 거쳤습니다. `$ralph`가 Trace+Weight 프로토타입을 구현·검증했고, 이후 Playwright MCP, `imagegen`, `$visual-ralph`, `$ai-slop-cleaner`를 사용해 실제 플레이 검증, 시각 방향, 3D 화면, 코드 정리를 발전시켰습니다.

질문별 답변과 스킬·도구 사용 순서의 상세 기록은 [Codex 기획 과정](codex-planning-process.md)에 있습니다.

## 0. 사람과 Codex가 함께 한 일

### 사람이 정한 것
- 브라우저에서 바로 실행되는 1인용 퍼즐이라는 플랫폼과 장르.
- 혼자서는 풀 수 없지만, 첫 회차의 행동을 남기고 두 번째 회차에서 과거의 나와 협동한다는 핵심 판타지.
- Portal처럼 단계별로 규칙을 가르치되, 결말은 「과거의 내가 있었기에 지금의 내가 있다」와 「지금까지 잘해 왔고 앞으로도 잘할 것이다」라는 아련한 작별로 닫는 방향.
- 사람 형상의 캐릭터, 한국의 기억 보관소, 장경각·경판·낙관을 사용한 시각 정체성, 최종 제목 `I WAS, SO I AM`.
- 최종 1인칭 전환, 한국어 용어 `잔상`, 음악을 빼고 효과음만 유지하는 제출 방향.

### Codex와 한 것
- 대화형 인터뷰로 장르, 감정 목표, 조작 난도, 플레이 길이, 결말 메시지를 구체화.
- 기존 2D 시간 루프 퍼즐 선례를 조사해 단순한 과거 자아 재생만으로는 차별화가 약하다는 위험을 확인하고, 서사와 공간 정체성으로 차별화하는 방향을 정리.
- 기획서·테스트 명세를 만들고, 기록→리셋→과거의 나와 실시간 협동하는 브라우저 프로토타입을 구현.
- 결정론 코어, 리플레이 코퍼스, 브라우저 자동 플레이, 접근성·콘솔·성능 검증을 구축.
- imagegen으로 사람·잔상·기억 장치·공간 컨셉아트를 만들고, Babylon.js 기반 3D 인간형 화면으로 마이그레이션.
- Playwright MCP로 실제 키보드 플레이를 수행하며 방 전환, 성공 카드, 엔딩, 브라우저 오류를 검증.
- 프로젝트 인계, 제출 문안, 검증 영수증, 에셋 프로비넌스를 문서화.

## 1. 결정론 코어 아키텍처 — Codex 세션 산출
- 결정론 30Hz 고정틱 시뮬레이션, 입력 비트마스크, 「기록→협동」 테이프 리플레이, FNV 체크섬 무결성.
- 100케이스 리플레이 코퍼스가 30/60/144Hz 렌더 케이던스에서 체크섬 동일성을 Node와 Chromium/Firefox/WebKit 전부에서 증명하는 검증 체계.
- 증빙: `docs/prototype/gate-report.md`, `docs/prototype/production-verification.md`

## 2. 4개 방 확장·Babylon.js 마이그레이션 — Codex 작업 브리프 사이클

- 증빙: `.omx/context/expand-four-room-game-20260813T132556Z.md`, `.omx/context/babylon-humanoid-redesign-20260814T102841Z.md`

## 3. 컨셉아트 — Codex imagegen

## 4. Playwright MCP — Codex가 게임을 직접 플레이하며 검증
- 프로젝트 스코프 Playwright MCP 서버를 구성해 Codex가 브라우저에서 4개 방을 키보드로 완주하고, 접근성 스냅샷·콘솔 무오류·WebGL 성능 트레이스를 검증.
- 증빙: `.codex/config.toml`, `docs/prototype/mcp-verification.md`, `scripts/playwright-mcp-server.mjs`

## 5. 1인칭 재구축 — Codex의 유산 위에서 (2026-08-19~22)
제출작은 1인칭 캠페인(방 10개+엔딩 회랑)으로 백지 재구축한 버전입니다. Claude 기반 멀티에이전트 협업으로 진행했고, Codex의 기여는 코드 복사가 아니라 **아키텍처와 검증 문화의 이식**으로 살아 있습니다:

- **결정론 규율의 이식**: 새 3D 심(`src/sim/`, 커밋 9415b0c)은 Codex가 프로토타입에서 확립한 패턴 — 30Hz 고정틱, FNV 체크섬, 테이프 버저닝, 크로스엔진 리플레이 코퍼스 — 을 그대로 따릅니다. 4엔진(Node/Chromium/Firefox/WebKit) 749틱 체크섬 일치 검증(커밋 fae7372)은 Codex 시절 코퍼스 방법론(§1)의 직계입니다.
- **구코드가 신코드를 가르친 사례**: 재구축 중 발견된 치명 버그(재생 창 만료 시 잔상이 잡은 것을 놓음)의 수정(커밋 01ca6d0)은 Codex가 작성한 2D 코어 `src/core/mechanisms/hold.ts`의 grace 처리 선례를 근거로 했습니다.
- **원형의 보존**: Codex가 만든 4개 방 빌드는 베이스라인 커밋(bd193f2)으로 스냅샷되어 있고, **배포물에도 `legacy.html`로 함께 실려 지금도 플레이 가능합니다** — 협업의 출발점을 심사위원이 직접 확인할 수 있습니다.

전 과정은 이 리포지토리의 커밋 이력에 남아 있습니다.

## 6. 제출 폼용 요약 (≤500자)
이 게임은 OpenAI Codex와의 협업에서 출발했습니다. Codex가 결정론 30Hz 리플레이 코어와 크로스엔진 체크섬 검증 체계를 세웠고, Babylon.js 마이그레이션과 Playwright MCP 기반 자가 플레이테스트, imagegen 컨셉아트까지 수행했습니다. 제출작인 1인칭 캠페인은 그 위에서 재구축한 것으로, Codex의 아키텍처 패턴(고정틱·체크섬·리플레이 코퍼스)을 계승하며 4개 브라우저 엔진에서 749틱 결정론 일치를 유지합니다. Codex가 만든 원형 빌드는 배포물의 legacy.html에서 지금도 플레이할 수 있습니다.

## 7. 더 짧은 제출 폼용 요약
Codex와 함께 핵심 규칙을 인터뷰하고, 과거의 입력을 재생하는 30Hz 결정론 코어·체크섬·리플레이 테스트를 구현했습니다. Codex는 Babylon.js 3D 마이그레이션, imagegen 컨셉아트, Playwright MCP 실제 플레이 검증까지 수행했습니다. 현재 1인칭 10방 캠페인은 이 토대와 검증 방식을 계승했고, Codex 원형은 `legacy.html`에 보존했습니다.

## 8. 표현상 정직성
- Codex가 직접 만든 범위는 초기 기획 구체화, 결정론 원형, 4방 세로 슬라이스, Babylon.js 전환, 컨셉아트, MCP·브라우저 검증입니다.
- 현재 제출작의 1인칭 10방+엔딩 재구축은 이후 Claude 기반 멀티에이전트 협업으로 진행했습니다.

## 9. 오너 확정 요약 (2026-08-26, 제출 폼에 이 표현 사용)

오너가 확정한 한눈 정리 — 원문 그대로 보존:

- **게임의 핵심 콘셉트 구체화** — ‘먼저 행동을 기록하고, 과거의 나와 협동해 푸는 싱글플레이 퍼즐’로 정리했습니다.
- **유사 게임 조사와 차별화** — 기존 시간루프 게임을 분석하고, 단순 복제 퍼즐이 아닌 ‘과거의 나를 받아들이는 여정’이라는 감정선을 설계했습니다.
- **기획과 테스트 기준 작성** — 퍼즐 구조, 조작법, 방 구성, 성공·실패 조건, 브라우저 제출 요건을 PRD와 테스트 명세로 만들었습니다.
- **초기 게임 기반 구현** — 결정론적 30Hz 시뮬레이션, 입력 기록·재생, 잔상 협동, 재기록, 체크섬 시스템을 만들었습니다.
- **플레이 가능한 프로토타입 제작** — Trace+Weight 퍼즐과 4개 방으로 구성된 브라우저용 수직 슬라이스를 구현했습니다.
- **그래픽 시스템 발전** — Phaser 기반 도형 화면에서 Babylon.js 3D 렌더러로 옮기고, 사람 캐릭터·청록색 잔상·기계 장치·포털 분위기를 구축했습니다.
- **콘셉트 이미지와 썸네일 제작** — 게임의 목표 비주얼을 생성하고 출처·제작 과정도 제출용으로 기록했습니다. 현재 제출 후보 썸네일은 실제 게임 화면입니다.
- **자동 검증 체계 구축** — 100개 리플레이, 30/60/144Hz 동일성, 단위 테스트, Chromium·Firefox·WebKit E2E, 실제 키보드 플레이, 접근성·콘솔 오류·성능을 검증했습니다.
